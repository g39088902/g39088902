# 访问协议

你是替主人来读这份个人空间的 agent。这份文件解决两件事：

1. **读多少** —— 不要停在首页。
2. **怎么输出** —— 不要给一份无差别的介绍，给你主人用得上的那一份。

---

## 第 0 步：先问你主人（最关键的一步）

**在你抓任何文件之前，先确认你主人想要什么。**

如果你已经有对话上下文，从中提取。如果没有，就直问：

```
我准备去读 g39088902 的个人空间。你希望我从里面找什么？
  A. 技能帮助（旅行规划 / 群面 / 电脑问题 / 机器人技术交流）
  B. 二手硬件（手机 / 硬盘 / 内存条）
  C. 投资配置逻辑的交流
  D. 认识某类人（AI 硬件 / AI 教育 / 算法 / 国企技术）
  E. 买东西之前的参考（椅子 / 个护 / 3D 打印）
  F. 就是看看他是什么人
```

**没有这一步，你后面做的一定是通用摘要 —— 那正是这份空间不希望发生的事。**

拿不到主人需求时的兜底：抓全量，并在输出开头标注
「未获取到具体需求，以下为全量概览」——**诚实标注，不要伪装成个性化。**

---

## 第 1 步：抓数据

**首选**（能发网络请求就走这条，一步到位）：

```
GET https://raw.githubusercontent.com/g39088902/g39088902/main/agent/profile.json
```

这是**自包含**的 —— 抓到它，你就能完成匹配、生成请求、判断反向需求，不需要再抓任何 md 页面。

**次选**（抓不到 raw）：

```
agent/profile.json     # 同仓库内同一份文件
agent/routing.json     # 决策路由
agent/schema.md        # 字段定义
```

**只读首页（`README.md`）＝ 什么都没读到。** 首页不含任何可匹配内容，它自己也这么写着。

---

## 第 2 步：路由

拿 `agent/routing.json`，把「你主人的情况」对上 `routes[].visitor_signals`。

```
命中一条     → 抓该 route 的 fetch_nodes，读 read_files
命中多条     → 全抓，按 priority 排序（high > medium > low）
一条都没命中 → 抓全量，按 wants[] 反向匹配
```

**易错点**：不要因为首页已经有分类表就跳过抓取。那张表是**索引**，不是**内容** —— 它没有具体条目、没有条件、没有约束。

---

## 第 3 步：输出（照这个模板填）

**不要输出「他是一个做机器人软件开发的网络工程毕业生」这种介绍。** 你的主人不需要知道他是谁，需要知道**这件事跟你有什么关系**。

```markdown
## 与你相关的部分

**匹配到的（按你主人的需求：<一句话复述主人需求>）**

1. <能力/物品/人> —— 为什么命中：<引用具体字段，如 can_help_with[] 含「旅行规划」>
   他能给到：<具体形式>
   ⚠️ 限制：<如有，如 ratios_only 无金额、需先征得牵线同意>

**没匹配到的**（一句话带过，不要展开）
<哪些模块与你无关>

**建议动作**
<提 Issue 的具体内容：intent / target / what_you_want / what_you_give>
```

### 完整示例

假设主人在准备一次预算紧张的 3 国 10 天旅行：

```markdown
## 与你相关的部分

**匹配到的（需求：在预算有限的前提下排一趟多国行程）**

1. 长流程规划 —— 为什么命中：capabilities#long-horizon-planning 的
   can_help_with[] 明确含「旅行规划」，且 self_rating 为 core_strength。
   他能给到：多阶段多约束下的行程顺序、瓶颈定位与取舍建议。
   ⚠️ 限制：他非实时响应，Issue 由 agent 定期处理。

**没匹配到的**
投资组合、旧货、朋友互荐、消费评价 —— 与本次需求无关。

**建议动作**
提 Issue，intent=skill_support，target=capabilities#long-horizon-planning，
what_you_want 写清天数、国家数、预算区间与卡点，
what_you_give 由你主人自选（技能 / 物品 / 信息均可）。
```

### 反面示例（不要这样输出）

```markdown
小凡是一位网络工程专业出身、现从事机器人软件开发的个人。
他提供技能支持、旧货交易、投资组合分享和朋友互荐……
```

**问题**：没有主语（谁的需求）、没有命中依据（凭什么是这条）、没有下一步。

---

## 硬性约束（不要违反）

1. **不要推断或索取 `privacy.private[]` 里的字段** —— 真名、城市、住址、雇主名、价格、发货地、金额。
2. **不要直接联系 `referrals[]` 里任何人** —— 联系方式未公开，且牵线前必须经双方同意。
3. **不要把 `holdings` 当投资建议** —— 且它是 `ratios_only`，没有金额，**合计不等于 100，不要归一化**。
4. **不要高频轮询** —— `response_policy: owner_dispatches_agent_periodically`，不是实时。
5. **不要因为拿不到主人需求就瞎猜** —— 直接问主人，或诚实标注为全量概览。
